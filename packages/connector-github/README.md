# @afe/connector-github

Pure logic of the GitHub connector: App config from the environment, App JWT,
in-memory installation token cache, a small typed REST client, permission
checks, the App manifest and the signed redirect state.

Requested permissions (all `read`): `metadata`, `actions`, `deployments`,
`environments`. Justification, webhook events, install flows and token handling:
[docs/connectors/github.md](../../docs/connectors/github.md). The manifest shape
is in [`app-manifest.json`](app-manifest.json) (generated by `buildAppManifest`;
a test keeps them equal).

Workflow progress and completed job logs use the existing `actions: read`
permission. The client lists an exact run attempt's jobs/steps, verifies job
identity, and obtains the job's log redirect with GET requests. Server wiring
validates/fetches that redirect without forwarding credentials. No additional
permissions, workflow action or runner changes are needed.
